# Troubleshooting and FAQ

Most problems are an old cached page, a slow connection or a device short of memory; the table gives the first thing to try.

| Problem | Try this |
|---|---|
| Something looks old or a new feature is missing | Check the version next to "LWK Viewer" at top left; press Ctrl+F5 (Windows) or Cmd+Shift+R (Mac). On iPad, close the tab and open it again |
| "Wrong email or password" | Check the email; ask an admin to <strong>Reset password</strong>. After 10 tries, wait 15 minutes |
| "You are not a member of this project" | Ask the project admin to add you |
| I cannot add or change issues | You are a <strong>Viewer</strong> on this project; ask the project admin for Member |
| "N waiting to save" | Your connection dropped. Keep the page open; it saves when the connection returns |
| The newest sheets or model are not there | The publish may still be running, or the server is preparing it; wait a few minutes and reload |
| 3D is slow or jerky on a computer | Untick models you do not need, use a floor plan, check <strong>While moving</strong> is on "follow the frame rate" |
| iPad or iPhone reloads the page by itself | It ran out of memory: open fewer models, stay on one floor, keep <strong>Light mode</strong> on; send the Performance report |
| An element cannot be clicked in a section | Only the visible side of the cut can be picked; move the cut or use the Model browser |
| The measure snaps to the wrong thing | Zoom in closer; hold still until the label shows <strong>corner</strong>, <strong>midpoint</strong> or <strong>edge</strong> |
| A Revit link is missing or misplaced | Check <strong>Apply link transforms</strong> is on; tell the BIM coordinator |
| Pages look different after switching to WebGPU | In Performance, press <strong>Drawing with</strong> to go back to WebGL (or add &amp;gpu=webgl to the address once) |
| A page is slow to open over a VPN or from home | The second visit is much quicker (the files stay in your browser). If first visits stay slow, ask IT to turn on HTTP/2 on the server's proxy |
| Search finds nothing | Type at least 2 letters; every word must match. You only see projects, lists and chats you are a member of |
| "Revit's LWK add-in is not listening" | The ids were copied instead: in Revit use <strong>Manage &gt; Select by ID</strong> and paste |
| WhatsApp import: "does not look like a WhatsApp chat export" | Use WhatsApp's <strong>Export chat</strong> file (.txt or .zip), not a screenshot or a forwarded message |
| A task or message link opens nothing | You may not be a member of that list, chat or project; ask its owner |
| There is no Delete for a message or a chat | Only the sender deletes a message. A group is deleted by its admins, a project channel or topic by the project's admins |

<strong>When you report a problem,</strong> send: the project, the page (Sheets or 3D), your device and browser, what you did, a screenshot, and on the 3D page the <strong>Performance → Copy</strong> report.

<strong>FAQ</strong>

- <strong>Does it change the Revit model?</strong> No. Publishing only reads the model. Only the LWK Issues window adds pins or clouds, and only when you ask.
- <strong>Who can see my markups?</strong> Everyone on the project, unless the markup is on a layer an admin has restricted.
- <strong>Does it send email?</strong> Yes, when the server's mail is set up: task assignments, @mentions, comments and completions on tasks you follow, and a daily list of tasks due. Teams posts as before.
- <strong>Can I use it offline?</strong> Yes, for a project downloaded to the device (see Working offline). Short drops are fine anyway: changes wait and save when the connection returns.
- <strong>Does the Messenger replace WhatsApp?</strong> It is for project work, next to the drawings and tasks. Messages can be sent to WhatsApp and brought in from it, but the two are not linked automatically.
- <strong>Can consultants use it?</strong> Yes, with their own account, usually as <strong>Viewer</strong> or <strong>Member</strong> on that project only.
